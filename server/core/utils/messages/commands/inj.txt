关于
    在 Windows 上注入远程进程。大多数模式需要 pid 以及文件或脚本。inj spawn 会创建挂起进程并向其中注
    入。分配选项与 migrate 相同。

用法：
    inj <shellcode|dll-reflective|donut> -f <file> -p <pid> [flags] --- [<args>]

参数：
    -f                  本地载荷文件（--file）。
    -p                  目标进程 ID（--pid）。
    -t                  inj spawn 使用的可执行文件（--target）。
    --alloc             section 或 stomp。省略则使用默认方式（virtual alloc）。
    --stomp-dll         alloc 为 stomp 时使用的 DLL 名称。
    --encoder           shellcode 和 donut 使用 sgn。

模式：
shellcode           从文件加载原始 shellcode。远程线程执行，不等待完成消息。
dll-reflective      x64 反射 DLL。在 ReflectiveLoader 或 KaynLoader 导出处启动远程线程。
donut               服务器通过 donut 将文件转换为 shellcode，随后走与 inj shellcode 相同的流程。

分配方式：
section             在目标进程中创建新节区并将载荷写入其中。
stomp               使用模块践踏（stomp）技术注入载荷。

示例：
    inj shellcode -f payload.bin -p 2300
    inj dll-reflective -f agent.dll -p 2300
    inj donut -f tool.exe -p 2300
    inj shellcode -f payload.bin -p 2300 --alloc section
    inj shellcode -f payload.bin -p 2300 --alloc stomp --stomp-dll apphelp.dll
    inj shellcode -f payload.bin -p 2300 --encoder sgn

NUKERAT 选项：
-w <秒数>       等待超时的最大时间
-bg             后台运行，不等待输出

示例：
    inj -w 180 shellcode -f file.bin -p 2300 --alloc section
